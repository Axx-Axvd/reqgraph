# Выполнение задачи T-xxx

Порядок упрощён решением автора 23.11: меньше ритуалов, быстрее до main.

1. Прочитай задачу в docs/backlog.md, связанные разделы docs/tech-design/ и ADR.
2. Обычной задаче — 3–5 строк «что делаю» и сразу работа. Полный план по [plans.md](plans.md) и «ок» — только если меняются схемы, зависимости, архитектура, миграции или это замер эксперимента (правило решения записывается до замера).
3. Ветка feat/T-xxx. Сначала тесты, потом реализация. Маленькие коммиты в Conventional Commits.
4. Локально — проверки затронутой части: ruff и mypy по изменённому, тесты своего пакета, `pnpm -C apps/web lint` и `build`, если задет сайт. Полный набор (pytest всего репозитория, e2e, Windows) гоняет CI. Временные файлы и скриншоты — только когда без них не проверить; скриншоты — один проход.
5. Документы: статус в docs/backlog.md — одной строкой («сделано ДД.ММ, PR #N»); docs/journal.md — только решения, замеры, отвергнутые гипотезы и неожиданности; CHANGELOG.md — одна строка, если изменение видно пользователю.
6. PR по шаблону. Мерж — по правилу CLAUDE.md «Кто мержит»: простую задачу Claude мержит сам после зелёного CI. Итог автору — коротко: что сделано, что от него нужно. Не трогай файлы вне задачи и examples/garage61.
