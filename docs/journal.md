**Решения**

В политиках `(select auth.uid())` — рекомендация Supabase: функция вычисляется один раз на запрос.

## 2026-10-23 · T-005: LLM-слой на pydantic-ai

**Решения**

- `reqgraph.llm.structured(role, prompt, output_type)` — единственный способ агентам вызвать модель. Строит из `roles.yaml` лестницу моделей роли (`FallbackModel` при двух и больше), просит объект Pydantic (ретраи невалидного ответа — `retries` из `defaults`), возвращает `CallStats`: модель, провайдер, токены, запросы, фактическая стоимость (0 на бесплатных тарифах), цена по прайсу genai-prices отдельно (ответ на замечание C16 этапа 0: «$0 занижает метрику»), латентность.
- Бюджет прогона — `RunBudget`: перед вызовом проверка остатка долларов и токенов, внутри вызова `UsageLimits(total_tokens_limit=остаток)`; превышение — `BudgetExceeded`. Встроенный в pydantic-ai `cost_limit` не взят: он считает цену по прайсу и для бесплатных моделей, остановил бы бесплатную разработку.
- У провайдера в `roles.yaml` появились `max_input_tokens` (Groq 6000: длинный промпт сразу идёт к следующей модели, а не ловит 429 при лимите 8000 токенов в минуту) и `supports_seed` (Gemini: 400 на `seed`). Seed задаётся в настройках каждой модели, а не прогона.
- Ключ — из переменной окружения; если её нет, уходит `placeholder` (в облаке ключ подставляет прокси). Ключи не логируются; кассеты проверены: заголовков `authorization` и `x-goog-api-key` нет.
- Groq проверяет вызовы инструментов на своей стороне: если модель назвала поле не так (`from` вместо `source`), ответ 400, и pydantic-ai не может переспросить. С `response_format: json_schema` (pydantic-ai NativeOutput) те же задания проходят на `gpt-oss-20b` и `gpt-oss-120b` — у провайдера в `roles.yaml` появился `output_mode` (Groq: native). Найдено пробным прогоном probe (T-006).
- Тесты без сети теперь через `--allow-hosts=127.0.0.1,::1` вместо `--disable-socket`: asyncio создаёт локальную пару сокетов (на Windows — TCP на 127.0.0.1), а `--disable-socket` запрещает создание любого сокета, и на Windows CI падали все async-тесты. Подключение к любому внешнему адресу по-прежнему блокируется (`SocketConnectBlockedError`, смоук-тест).
- Импорт `reqgraph.llm`: 36 → 68 МБ RSS (+32 МБ; ADR-013 оценивал +57 МБ вместе с полным pydantic-ai).

**Проблемы**

- При записи кассет 23.10: `minimax/minimax-m3.1-flash:free` снят с бесплатного тарифа 22.10, `nvidia/nemotron-3-super-120b-a12b:free` отвечает 404. Проверил вживую 5 бесплатных моделей OpenRouter, в профиль `free` взял `nemotron-3.5-super-vl:free`, `nemotron-3-ultra-550b-a55b:free`, `dots-3-note-preview:free`. Выбор временный — до probe (T-006).
- В тестах с кассетами pytest-socket предупреждает о попытке открыть сокет: попытку перехватывает и гасит сама библиотека, ответы идут из кассет, тесты проходят без сети. Источник не искал — не влияет на результат.

## 2026-10-23 · T-006: probe моделей на pydantic-evals

**Решения**

- `evals/` — отдельный участник uv workspace (`reqgraph-evals`): по слоям CLAUDE.md это входной слой, ядро от него не зависит. Поэтому команда — `uv run reqgraph-evals probe`, а не `reqgraph probe`, как было в бэклоге.
- 20 заданий (4 блока по 5) на доменах, которых нет среди 15 сценариев диплома: фитнес-клуб, коворкинг, прокат велосипедов, школа танцев, ЖКХ, типография, приют для животных, музей, турагентство.
- Оценки детерминированные: F1 по эталону для извлечения, структура и полнота процесса, «должна», размытые слова, критерии и измеримость для переписывания, правила для вопроса. LLM-судья — только по флагу `--judge`, в первый прогон не включался (экономим бесплатные лимиты Gemini).
- В CSV сохраняется ответ модели: оценки можно перепроверить вручную и пересчитать командой `rescore` без повторных вызовов.
- `structured(..., model_id=...)` — одна модель без фолбэка, чтобы сравнивать модели на одних и тех же задачах.

**Пробный прогон (gpt-oss-20b) нашёл и исправил**

- ответы по-английски — во все промпты добавлено «Отвечай на русском языке»;
- Groq отклонял неточные вызовы инструмента (400 без повтора) — для Groq включён вывод через JSON Schema (`output_mode: native`, см. T-005);
- лимит Groq 8000 токенов в минуту — probe ждёт `retry-after` и повторяет (до 4 раз);
- посимвольное сравнение с эталоном не узнавало пересказ — сравнение по основам слов;
- правильный вопрос считался «не по теме» — тема задаётся списком основ.

**Основной прогон 23.10** (`evals/reports/probe-2026-10-23-free-x3.csv` и `-openrouter-x1.csv`): gpt-oss-120b, gpt-oss-20b, gemini-3.5-flash-lite — по 3 повтора; nemotron-3.5-super-vl:free — 1 повтор (лимит OpenRouter 50 запросов в день). ## 2026-10-23 · T-101: граф артефактов и патчи

**Что сделано.** `reqgraph.graph`: 12 видов узлов, 6 видов связей с таблицей допустимых пар, `GraphPatch` из пяти операций, `ArtifactGraph.apply()` («всё или ничего»), `IdAllocator`, блокировка утверждённых узлов для агента, стабильный JSON. Схемы `schemas/graph-patch.schema.json` и `schemas/artifact-graph.schema.json` (версия 1) создаёт `uv run reqgraph schemas`, тест следит за актуальностью. Тесты написаны раньше кода: 137 в `packages/core/tests/graph`, покрытие `graph/` 96%.

**Три решения, согласованные в плане.** (1) Добавлена операция `unlink` — без неё ошибочную связь не исправить, не удаляя узел. (2) `remove` каскадом убирает связи узла, в отчёт об изменении они попадают. (3) `apply()` возвращает `ApplyResult(graph, id_map, diff)`; пример в 03_agents поправлен.

**Решения по ходу работы.**
- Номера не повторяются, даже если у `apply()` свежий `IdAllocator`: «высшие отметки» счётчиков лежат в самом графе (`high_water`) и в JSON.
- Агент не может каскадом убрать связь утверждённого узла: удаление реплики `TURN-0001` отклоняется, пока от утверждённого `FR-001` на неё есть `derived_from`. `conflicts_with` симметрична, поэтому утверждённый узел защищён с обеих сторон — если агент нашёл конфликт с утверждённым требованием, связь создаёт человек.
- Связь с несуществующим узлом, неверным видом, поле-ссылка (`UR.actor`) на несуществующего актора — отказ всего патча с сообщением на русском и id узла.
- Пункт 16 preflight («главная запись связи требование→модель — `realized_by`») только заложен: тип связи есть, сверка с зеркалом `realizes` в DSL — TRC-004 в T-107.

**Допущения.** Таблица допустимых пар видов может оказаться строже эталона garage61 — это вскроет T-102 (загрузка эталона); тогда править таблицу, а не эталон (эталон правит только автор). Существование подэлемента процесса (`PRC-01.T03`) здесь не проверяется — только родитель; задача T-103/T-107.

**Что дальше.** После мержа — T-102 (FileStore и garage61): нужна проверка автором черновика эталона по `examples/garage61/REVIEW.md`.

## 2026-10-23 · T-102: FileStore — проект как папка

**Что сделано.** `reqgraph.graph.store`: `FileStore(папка).load()` собирает `Project` — настройки `reqgraph.yaml` (новая публичная схема `project-config`, версия 1), граф и тексты файлов; `save()` пишет обратно. Эталон garage61 читается в корректный граф: 3 ACT, 3 BR, 4 UR, 14 FR, 5 NFR, 3 CON, 2 PRC, 8 ENT, 8 UC, 6 C4, 32 TURN, 88 связей — все допустимы по таблице T-101. 48 тестов в `packages/core/tests/store`, покрытие store 90–100%.

**Решения по ходу работы.**
- План говорил «файлы записываются в едином виде, комментарии теряются». Сделал лучше: файл, содержимое которого не изменилось, пишется **байт в байт** (комментарии и ручное оформление сохраняются); изменённый — в каноническом виде. Канонический вид повторяет оформление эталона: на garage61 он совпадает с оригиналом во всех файлах, кроме порядка id внутри `realized_by` (у меня — по алфавиту). `ruamel.yaml` не понадобился.
- Запись в новую папку даёт точную копию эталона (тест сравнивает байты), запись «на место» ничего не меняет.
- Узлы ENT/UC/C4 читаются временным сканером по соглашениям REVIEW.md №3; если граф меняет такой узел, `save()` отказывает с понятной ошибкой — файл диаграммы из графа пока не пишется (T-104), а молча терять изменения нельзя.
- Новый процесс без id в DSL получает id узла при записи (агент не знает id заранее — он выдаётся кодом).
- Посторонние файлы в `models/` (картинки) не читаются: проект владеет только `.dbml`, `.puml`, `.dsl`, `.bpmn`, `.svg` и `*.process.json`.
- Небольшая правка ядра графа: разбор узлов с понятной ошибкой переехал в `nodes.py` (`node_from_dict`), добавлен `ArtifactGraph.from_parts()` — загрузка не может идти через патч, потому что id приходят из файлов.

**Расхождение с бэклогом (согласовано).** «Эталон проходит все проверки» — в T-107, когда появятся проверки.

**Допущения.** `refines` в DSL процесса — метаданные DSL, а не связь графа (таблица связей T-101 не разрешает PRC → UR); сверку с требованиями сделает T-107. Разделы SEC и связи `rendered_in` на диск не пишутся.

**Что дальше.** T-103: DSL процессов и компилятор BPMN. Эталон по-прежнему ждёт проверки автора (до T-107).

**Что сделано.** `reqgraph.dsl`: модель DSL v1 (`ProcessDSL`, публичная схема `process-dsl`), компилятор в BPMN 2.0 с дорожками и раскладкой, проверка по официальным XSD OMG, команда `reqgraph bpmn`. **Решения по ходу работы.**
- XSD: сайт OMG закрыт прокси облачной сессии; файлы взяты из jar `camunda-bpmn-model` 7.24.0 (Maven Central, Apache-2.0), суммы sha256 — в `dsl/xsd/README.md`, тест сверяет их. Хуки pre-commit `trailing-whitespace` и `end-of-file-fixer` правили бы файлы OMG (в трёх есть пробелы в конце строк) — папка исключена из хуков.
- Раскладка, первая версия, на скриншотах: подписи «да»/«нет» одного шлюза накладывались (стояли у начала стрелки), а в PRC-02 стрелка «клиент отменил → перевести в «отменена»» входила на одной высоте со стрелкой таймера — казалось, что таймер ведёт к отмене. Исправлено: подпись — у входа в целевой шаг; шаги одной колонки и дорожки упорядочиваются по высоте предшественников (барицентр); обратные стрелки петель идут по промежутку между рядами, а не по краю фигур.
- `exporterVersion` в BPMN не пишется: иначе golden-файлы менялись бы с каждой версией пакета.
- mypy: у lxml и networkx нет подсказок типов, stub-пакеты отстают от закреплённых версий — `ignore_missing_imports` только для них.
- Сообщения своих валидаторов Pydantic теперь без префикса «Value error,» (касается и графа).

**Проверка в bpmn-js.** Не в CI: tarball `bpmn-js@18.31.1` из npm, Playwright + Chromium, `importXML` для всех golden — 0 предупреждений; скриншоты PRC-01 и PRC-02 — в PR. Встроить такую проверку в CI можно в T-505, когда bpmn-js появится в `apps/web`.
