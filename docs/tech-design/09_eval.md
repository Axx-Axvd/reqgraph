# 09 Evaluation

*как оцениваем систему и насколько объективно хорош сам проект*

## Часть А. Оценка системы

### Гипотезы

| # | Гипотеза | Сравнение | Метрика и тест |
|---|---|---|---|
| `H1` | интервьюер с трекером покрытия находит больше скрытых требований | M2 vs M1, B3 | recall; Wilcoxon, 45 пар |
| `H2` | цикл CI-ремонта повышает долю корректных моделей | M1 vs B2 | validity, soundness; Wilcoxon |
| `H3` | проверки трассировки устраняют рассогласование текста и моделей | M1 vs B2, абляция -TRC | trace coverage, orphan rate |
| `H4` | документы reqgraph не хуже черновика junior-аналитика при x10 меньшем времени | M2 vs B0 | оценки экспертов, граница не хуже на 0.5 балла |

### Методы сравнения

| Код | Метод | Как устроен |
|---|---|---|
| `B0` | Junior-аналитик | человек получает те же диалоги, 2-3 сценария, замер времени |
| `B1` | LLM one-shot | бриф + транскрипт -> документ одним промптом |
| `B2` | MAS без проверок | те же агенты, без CI и ремонта (как iReDev-подобный конвейер) |
| `B3` | Бакалаврская система | фиксированная анкета 10-15 вопросов -> требования |
| `M1` | reqgraph | свободное LLM-интервью + CI + ремонт + трассировка |
| `M2` | reqgraph + покрытие | M1 + интервьюер с трекером покрытия (основная версия) |
| `A1-A3` | абляции M2 | без ремонта; без TRC-*; без Reviewer (шаблонные задачи) |

### Метрики

| Метрика | Формула | Источник |
|---|---|---|
| `recall` | \|найдено пересечь скрыто\| / \|скрыто\| | сопоставление: эмбеддинги -> судья -> ручная выборка 20% |
| `precision (доп.)` | доля извлечённых, подтверждённых эталоном или экспертом | судья + эксперт |
| `ambiguity` | доля требований с нарушениями ISO-001..004 | проверки |
| `validity` | доля моделей без ошибок SCH-* | проверки |
| `soundness` | доля процессов без ошибок SND-* | проверки |
| `trace coverage` | доля ФТ с realized_by | TRC-002 |
| `orphan rate` | доля элементов моделей без требований | TRC-003 |
| `completeness` | доля обязательных разделов SRS / ТЗ | TPL-* |
| `expert score` | 6 критериев Лайкерта 1-5, 3 эксперта, слепо | форма; каппа Флейса (3 эксперта) >= 0.4, statsmodels |
| `efficiency` | recall на 10 вопросов; $ и минуты на прогон | run_events |

### Пороги приёмки (MVP / диплом)

| Метрика | Порог MVP | Цель диплома |
|---|---|---|
| Recall скрытых требований | ≥ 70% | ≥ 85% |
| Validity моделей (SCH) | ≥ 95% | ≥ 100% |
| Soundness процессов (SND) | ≥ 80% | ≥ 95% |
| Trace coverage ФТ | ≥ 80% | ≥ 95% |
| Неоднозначные требования | ≤ 15% | ≤ 5% |

<sub>Протокол: 15 сценариев (3 dev для настройки, 12 test только для отчёта), 3 персоны, seed фиксирован, одна модель для всех методов, повтор 3 прогонов для 3 сценариев — оценка разброса. Значимость p < 0.05 с поправкой Холма на 4 гипотезы; к каждому тесту — размер эффекта.</sub>

<sub>Инструменты (ADR-013, этап 0): харнес, датасеты и LLM-судья — pydantic-evals; эмбеддинги для сопоставления recall — `gemini-embedding-001` (Google AI Studio, бесплатно); Wilcoxon и поправка Холма — scipy и statsmodels; согласие экспертов — каппа Флейса (statsmodels). GPL-пакеты (pingouin, krippendorff) не используем.</sub>

### SWOT

| `S · сильные`  проверяемость вместо «красивого текста»; одна модель данных на два стандарта; продолжение бакалаврской; всё открыто и воспроизводимо | `W · слабые`  новизна частичная; симулятор заказчика — приближение; качество русскоязычного текста у дешёвых моделей; один автор |
|---|---|
| `O · возможности`  статья или техотчёт; инструмент для кафедры и студентов; MCP-интеграция с Jira / Confluence; кейс для собеседований аналитика | `T · угрозы`  похожая работа выйдет раньше; коммерческие инструменты добавят такие проверки; изменение бесплатных тарифов; ограничения доступа |

### Критерии разворота

- **M2 (29.11):** если soundness на dev < 50% даже после ремонта — сузить модели до процессов и ERD, остальные нотации убрать из диплома.

- **M3 (13.12):** если recall на живом интервью отличается от симулятора больше чем на 20 п.п. — главной оценкой интервью сделать живые сессии, симулятор оставить для абляций.

- **M4 (27.12):** если расход выходит за $20 в месяц — профиль free и 9 сценариев вместо 15.

> [!IMPORTANT]
> Итог: проект сильный по проверяемости и практической ценности, средний по новизне. Главное, что сделает его убедительным для комиссии и зарубежных программ, — честный эксперимент с бейзлайнами и абляциями, а не число поддерживаемых нотаций.
