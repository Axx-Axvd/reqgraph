# 05 Checks

*каталог проверок, интерфейс, отчёт и цикл ремонта*

Проверки — сердце проекта и главный аргумент новизны. Все они детерминированные: одинаковый граф всегда даёт одинаковый отчёт. Единственное исключение — опциональный LLM-судья в ISO-002, который в экспериментах считается отдельно.

## Интерфейс проверки

**`packages/core/src/reqgraph/checks/base.py`**

```python
class Finding(BaseModel):
    check_id: str                    # "TRC-002"
    severity: Literal["error", "warning", "info"]
    node_ids: list[str]
    message: str                     # человекочитаемо, по-русски
    hint: str | None = None          # как починить, для Reviewer
    owner: Literal["analyst", "modeler", "standards"]
    @property
    def fingerprint(self) -> str:    # для детектора повторов
        return sha1(f"{self.check_id}|{sorted(self.node_ids)}")

class Check(Protocol):
    id: str; title: str; applies_to: set[NodeKind]
    def run(self, g: ArtifactGraph, ctx: CheckContext) -> list[Finding]: ...

@register                           # checks/registry.py собирает все
class FrRealized:
    id = "TRC-002"; title = "ФТ реализованы в моделях"; applies_to = {NodeKind.FR}
    def run(self, g, ctx):
        return [Finding(check_id=self.id, severity="error", node_ids=[fr.id],
                        message=f"{fr.id} не реализовано ни одним элементом модели",
                        owner="modeler") for fr in g.nodes(NodeKind.FR)
                if not g.out_edges(fr.id, "realized_by")]
```

## Цикл ремонта

**`agents/reviewer.py — логика ci_gate и reviewer`**

```python
def ci_gate(s: RunState) -> str:
    errors = [f for f in s["ci"].findings if f.severity == "error"]
    if not errors or s["iteration"] >= MAX_ITER or s["ci"].needs_human:
        return "done"                       # экспорт с отчётом в любом случае
    return "repair"

async def reviewer(s: RunState, rt: Runtime) -> dict:
    fps = {f.fingerprint for f in s["ci"].findings}
    if fps and fps <= rt.history.last_fingerprints(2):   # нет прогресса
        return {"ci": s["ci"].mark_needs_human()}
    groups = group_by_owner(s["ci"].findings, limit=10)
    tasks = await rt.llm.structured(role="reviewer", output_type=list[RepairTask],
                                    prompt=render(REVIEW_PROMPT, groups=groups))
    return {"tasks": tasks, "iteration": s["iteration"] + 1}
```

<sub>Почему Reviewer — LLM, а не таблица правил: детерминированно известны владелец и узлы, но формулировку задачи («объедини NFR-003 и NFR-005, добавь порог p95») удобнее поручить модели. В абляции «без Reviewer» задачи строятся шаблоном — это даст честную оценку его вклада.</sub>

## Как тестируются проверки

- у каждой проверки есть папки fixtures/good/ и fixtures/bad/ — маленькие графы, на которых она должна молчать или срабатывать;

- мутационные тесты: из эталона garage61 автоматически ломаем граф (удалить ребро, добавить «быстро», оборвать ветку шлюза) и ждём конкретный check_id;

- покрытие кода для checks/ и dsl/ — не ниже 90%; отчёт CI — стабильный JSON (snapshot-тесты).
