# 00 README

*что строим, зачем, как и к какому сроку*

**reqgraph** — мультиагентная система, которая проводит интервью с заказчиком, формулирует БТ, ПТ, ФТ и НФТ, строит модели процессов, данных и архитектуры как код, прогоняет всё через детерминированные проверки (CI для требований) и собирает SRS по ISO/IEC/IEEE 29148 и ТЗ по ГОСТ 34.602-2020 из одного графа артефактов. Этот документ — технический проект и дорожная карта: по нему можно начинать писать код, в том числе с Claude Code.

- **5 + 1** — агентов: Interviewer, Analyst, Modeler, Standards, Reviewer + симулятор заказчика для оценки
- **21** — детерминированная проверка: схема, soundness, ISO 29148, трассировка, шаблоны
- **$0-20** — в месяц: бесплатные тарифы + дешёвые open-weight модели через OpenRouter
- **21.02** — релиз v1.0, результаты экспериментов и черновик текста диплома; буфер до 28.02

## Какие проблемы решает

<p align="right"><sub>Таблица 1 - боль аналитика -> механизм reqgraph -> как проверяем</sub></p>

| Проблема | Что делает reqgraph | Проверка |
|---|---|---|
| Требования теряются между интервью и документом | каждое требование — узел графа с id и ссылкой на реплику интервью (derived_from) | TRC-006 |
| Модели рисуют отдельно, и они расходятся с текстом | модели — код (DSL, DBML, PlantUML, Structurizr), связаны с ФТ рёбрами realized_by | TRC-002, TRC-003 |
| LLM-генераторы дают гладкий, но непроверенный текст | 21 детерминированная проверка + цикл ремонта до зелёного отчёта | весь 05_ci |
| Интервью идут по памяти: забывают НФТ и исключения | трекер покрытия по 9 областям выбирает, о чём спросить дальше | recall на скрытых наборах |
| Шаблоны ГОСТ и ISO заполняют вручную, дважды | один граф -> два экспортёра, проверка полноты разделов | TPL-001, TPL-002 |
| Правки ломают согласованность | ревизии графа, повторный прогон CI после любой правки | diff ревизий |

## Ключевые решения (ADR)

<p align="right"><sub>Таблица 2 - архитектурные решения; подробности — в docs/adr/ репозитория</sub></p>

| ADR | Решение | Почему так |
|---|---|---|
| `001` | Монорепо: Python-ядро (uv) + Next.js (pnpm), MIT, публичный с первого дня | одна история коммитов для диплома и CV; Claude Code видит весь контекст |
| `002` | Оркестрация на LangGraph (StateGraph, interrupt, Postgres-чекпоинтер) | паузы интервью, возобновление после сна сервера, граф виден в коде |
| `003` | LLM через тонкий роутер; реализация — pydantic-ai (ADR-013); без LangChain-обёрток | все провайдеры OpenAI-совместимы; меньше памяти на бесплатном хостинге |
| `004` | Единый источник правды — ArtifactGraph (Pydantic); агенты возвращают патчи, а не текст | детерминированные id, атомарные правки, понятный diff |
| `005` | Процессы: LLM пишет JSON DSL, BPMN XML генерирует компилятор | LLM плохо пишут валидный BPMN XML (BEF4LLM); компилятор даёт 100% схемы |
| `006` | Проверки не вызывают LLM (кроме опц. ISO-002) | воспроизводимость и честная метрика качества |
| `007` | Хранение: Supabase (Postgres jsonb-ревизии, Auth, Storage, Realtime) | бесплатно, RLS из коробки, локальный стек через Supabase CLI |
| `008` | Деплой: Vercel (web) + Render free (api + worker); локально docker compose | $0; для защиты в РФ — офлайн-стенд без зависимостей |
| `009` | Фоновые задачи: очередь в Postgres (SKIP LOCKED), без Redis | один сервис на бесплатном тарифе, меньше движущихся частей |
| `010` | Диаграммы: bpmn-js в браузере, Kroki для SVG остальных нотаций | не тащим Java и Graphviz в контейнер |
| `011` | Модели: open-weight по ролям, выбор по своему мини-бенчмарку; один и тот же LLM для всех методов в эксперименте | дёшево и честно: сравниваем методы, а не модели |
| `012` | Тексты стандартов в репозиторий не кладём — только свои чек-листы и структуры разделов | авторское право ISO; ГОСТ — ссылками |
| `013` | LLM-слой на pydantic-ai: structured output, FallbackModel, лимиты, цена | меньше своего кода; instructor несовместим с актуальным openai SDK |
| `014` | Soundness через pm4py с переводчиком DSL (событийный шлюз → xor) | не пишем свою сеть Петри; AGPL совместима с открытым проектом |
| `015` | ~~Демо на Streamlit~~ — **отклонено автором** 21.10.2026; действуют 008 и 009 | для портфолио важнее полноценный веб-стек |
| `016` | Экспорт DOCX через pandoc из Markdown | шаблон пишется один раз, без вёрстки DOCX вручную |
