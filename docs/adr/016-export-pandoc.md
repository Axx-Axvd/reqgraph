# ADR-016: Экспорт DOCX через pandoc

- Статус: принято (2026-10-21, решение автора: «готовые средства»)
- Дата: 2026-10-21
- Уточняет: стек экспорта из 02_arch.md (было: docxtpl + python-docx)

## Контекст

По плану SRS (ISO/IEC/IEEE 29148) и ТЗ (ГОСТ 34.602-2020) собирались в DOCX через docxtpl (LGPL) по вручную свёрстанным DOCX-шаблонам. Вёрстка и поддержка двух DOCX-шаблонов с циклами и таблицами — заметная ручная работа.

## Решение

- Текст документа собирается из графа Jinja2-шаблоном в Markdown (`exporters/templates/srs.md.j2`, `tz_gost34.md.j2`); Markdown-версия и так нужна.
- DOCX получается из Markdown через pandoc (`pypandoc-binary` 1.17, MIT; pandoc 3.9 внутри wheel, есть сборки для Windows и Linux). Стили — шрифт, поля, заголовки, оформление таблиц по ГОСТ — задаются одним `reference.docx`.
- Таблица трассировки — обычная Markdown-таблица (pipe table).
- Проверено 21.10: `pypandoc.convert_text(md, "docx")` с таблицей работает.

## Последствия

- T-401/T-402 (выгрузка SRS и ТЗ): шаблон пишется один раз в Markdown, DOCX — бесплатно.
- Минус docxtpl и python-docx; плюс ~40 МБ на диске за бинарник pandoc (память не растёт: pandoc запускается отдельным процессом).
- Тонкая вёрстка (колонтитулы, рамки по ГОСТ 2.104) ограничена возможностями `reference.docx`. Для учебного ТЗ этого достаточно; это вопрос к руководителю о строгости структуры ТЗ (10_claude, открытые вопросы).

## Альтернативы

- docxtpl + DOCX-шаблоны — полный контроль вёрстки, больше ручной работы.
