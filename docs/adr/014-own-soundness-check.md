# ADR-014: Своя проверка soundness по DSL, pm4py — только в тестах

- Статус: **предложено** (ждёт решения автора)
- Дата: 2026-10-21
- Уточняет: [ADR-005](005-process-dsl.md), [ADR-006](006-deterministic-checks.md); меняет реализацию SND-002 из 05_ci.md
- Источник: [docs/research/2026-10-versions.md](../research/2026-10-versions.md)

## Контекст

В 05_ci.md проверка SND-002 устроена так: «pm4py: BPMN → сеть Петри → check_soundness». Проверка 21.10.2026 нашла три проблемы:

1. **Лицензия.** pm4py 2.7.23 распространяется по AGPL-3.0-or-later. Репозиторий под MIT, публичное веб-демо работает как сетевой сервис. AGPL требует открыть исходники всего приложения пользователям сети: у нас они открыты, но MIT-лицензия проекта фактически перестаёт действовать для сборки с pm4py. Это нужно либо принять осознанно, либо обойти.
2. **Память.** Импорт pm4py добавляет +160 МБ RSS и занимает 5,6 с: тянет pandas, scipy, matplotlib, cvxopt и graphviz. Render Free даёт 512 МБ.
3. **Покрытие нотации.** Конвертер pm4py BPMN → Petri net обрабатывает только Task, Start/End и шлюзы Exclusive/Parallel/Inclusive. `EventBasedGateway` и промежуточные события (timer, message) он пропускает, а они есть в DSL v1 и в PRC-02 эталона garage61.

## Решение

- `dsl/soundness.py` строит workflow net прямо из DSL процесса:
  - task, user_task, service_task, timer, message — переход;
  - xor и event_based — место с несколькими выходами;
  - and — переход split/join.
- Soundness проверяется перебором достижимых маркировок. Процессы маленькие (десятки узлов), так что пространство состояний мизерное.
- Проверяемые свойства:
  - option to complete;
  - proper completion;
  - нет мёртвых переходов.
- Ограничение размера: если маркировок больше N, проверка возвращает info «слишком большой процесс».
- pm4py остаётся **dev-зависимостью**: в тестах результат своей проверки сверяется с pm4py на процессах без событийных шлюзов (golden и hypothesis). В runtime-зависимостях и Docker-образе pm4py нет.

## Последствия

- Лицензия runtime остаётся чистой (MIT + совместимые), образ меньше на ~160 МБ памяти.
- Около 150–200 строк своего кода в `dsl/`, покрытие ≥ 90% по правилу проекта.
- Событийный шлюз и таймеры PRC-02 проверяются корректно.
- Для диплома это плюс: алгоритм проверки описан и реализован самостоятельно, а pm4py служит независимой сверкой.

## Альтернативы

- Оставить pm4py в runtime и принять AGPL для всего проекта — проще в коде, но +160 МБ и нет поддержки событийных шлюзов.
- Перед конвертацией заменять event_based на xor, а события на задачи — костыль; лицензия и память не меняются.
