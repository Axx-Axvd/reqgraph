Веха M2 (S2): из брифа получаем граф требований, модели и зелёный — или объяснённый — отчёт проверок.
Интервью с заказчиком появится в S3 (T-301), документы SRS и ТЗ — в S4 (T-401).

## Как повторить

Нужны `uv sync` и ключи бесплатных провайдеров в `.env` ([docs/setup/accounts.md](../setup/accounts.md)):
Analyst и Modeler идут к Gemini, Standards и Reviewer — к Groq (`llm/roles.yaml`, профиль free).
Стоимость прогона на бесплатном профиле — $0; бюджет ограничивает `REQGRAPH_RUN_BUDGET_USD` или
`--budget-usd`.

```bash
uv run reqgraph init demo/bakery --name "Пекарня «Колосок»" --brief evals/scenarios/dev-02/brief.md
uv run reqgraph run demo/bakery
uv run reqgraph check demo/bakery --offline        # те же проверки ещё раз, без LLM
uv run reqgraph bpmn demo/bakery/models/processes/PRC-01.process.json -o PRC-01.bpmn
uv run reqgraph render demo/bakery/models/data/erd.dbml -o erd.svg     # нужен Kroki (KROKI_URL)
```

Полезные ключи `reqgraph run`: `--reviewer template` (ремонт без LLM: задачи по шаблону),
`--max-iter N` (кругов ремонта), `--no-write` (ничего не записывать), `--json` (сводка для скриптов),
`--offline` (проверки без сети: Kroki не вызывается). Код выхода: 0 — ошибок нет, 1 — ошибки
остались, и они объяснены в `reports/ci-report.md`, 2 — прогон не начался (нет брифа, эталонный
проект). На эталоне `examples/garage61` агенты не запускаются — только проверки.

Ответы LLM недетерминированы: повторный прогон даст другой граф и другие числа.

## Что лежит в проекте после прогона

| Путь | Что |
|---|---|
| `brief.md`, `reqgraph.yaml` | бриф и настройки проекта (`reqgraph init`) |
| `interview/transcript.jsonl` | абзацы брифа как реплики заказчика (TURN-…) |
| `requirements/*.yaml` | BR, UR, FR, NFR, CON и роли с источниками и связями |
| `models/processes/*.process.json` | процессы в нашем DSL (из них `reqgraph bpmn` делает BPMN 2.0) |
| `models/data/erd.dbml` | модель данных; у таблиц `Note: 'ENT-xx · название'` |
| `trace/edges.yaml` | связи трассировки (refines, realized_by, derived_from…) |
| `reports/ci-report.md`, `.json` | отчёт проверок последнего круга |
| `reports/run-summary.json` | сводка прогона: модели, хэши промптов, температура, seed, токены, $, время |
| `reports/run-events.jsonl` | события прогона по шагам (вызовы LLM, самопроверка, ремонт) |

Разделы SRS (SEC) пока живут только в графе прогона: в проект их запишет экспорт документов (T-401).

## Почему SVG, а не GIF

В бэклоге T-206 стоит «README-гиф». Записать GIF терминала можно только отдельной программой
(vhs, asciinema + agg), которой нет в зависимостях проекта, а сам GIF весит сотни килобайт и не
поддаётся правке. SVG собирается из сохранённого текста вывода тем же `rich`, что уже стоит вместе с
typer, весит ~13 КБ, текст в нём можно выделить и найти поиском, а GitHub показывает его в README.
Анимации нет — шаги прогона видны построчно.
