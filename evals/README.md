# evals — оценка reqgraph

Входной слой проекта: зависит от `reqgraph`, сам `reqgraph` отсюда ничего не импортирует.

## Probe — мини-экзамен для моделей (T-006)

20 заданий в 4 блоках по 5 (`probe/cases.yaml`): извлечь требования из фрагмента интервью, описать процесс графом, переписать требование по ISO 29148, задать уточняющий вопрос. Оценки детерминированные, без LLM (`reqgraph_evals/scoring.py`); LLM-судья для переписанных требований — только с флагом `--judge`, отдельной колонкой.

```bash
uv run reqgraph-evals probe --models groq/openai/gpt-oss-120b,gemini/gemini-3.5-flash-lite --repeat 3
uv run reqgraph-evals rescore evals/reports/probe-YYYY-MM-DD.csv   # пересчёт оценок по сохранённым ответам
```

Отчёт: `reports/probe-YYYY-MM-DD[-tag].csv` — строка на задачу и повтор (модель, провайдер, температура, seed, хэш промпта, версия пакета, токены, $ факт и по прайсу, латентность, оценки, ответ модели) и `.md` со сводкой. Числа в документах — только из этих CSV.

Ограничения: сопоставление требований с эталоном — по основам слов (5 первых букв), проверки процесса и размытых слов временные — до настоящих проверок SCH/SND (T-106) и ISO (T-107); probe повторяется с ними в T-601. Задания не пересекаются с 15 сценариями диплома (T-303).

## Сценарии (T-303)

15 сценариев — `scenarios/` (формат, домены и печать test-сценариев — в [scenarios/README.md](scenarios/README.md)):

```bash
uv run reqgraph-evals scenarios          # проверка формата и протокола; код 1 при проблемах или нарушенной печати
uv run reqgraph-evals scenarios --seal   # переписать печать test-сценариев — только после проверки автором
```

## Интервью с симулятором заказчика (T-302)

```bash
uv run reqgraph-evals interview --scenarios dev-01 --max-turns 20                 # 3 характера
uv run reqgraph-evals interview --characters vague --interviewer free --tag m1    # без трекера покрытия (M1)
```

Интервьюер задаёт вопросы, симулятор отвечает по скрытым требованиям сценария, Analyst пишет требования после каждого ответа, затем весь конвейер. Отчёт `reports/interview-YYYY-MM-DD-<профиль>-<интервьюер>[-tag].csv|md` — строка на сценарий, характер и повтор: модели всех ролей, температуры агентов и симулятора, seed, хэши промптов, версия пакета, вопросов, чем кончилось интервью, сколько скрытых требований (вне брифа) рассказано полностью, только упомянуто, сколько неверных чисел не поправлено, сколько рассказанного не в области вопроса, покрытие, требований в графе, ошибок проверок, вызовы, токены, $ и время. Диалоги для ручной проверки — `reports/dialogs/<имя отчёта>/`: каждый ответ с тем, что и как он рассказал; проекты прогонов — `runs/<дата>/interview/` (не в git), из них считает метрики T-304. Test-сценарии этой командой не запускаются.

## Analyst на dev-брифах (T-202)

Три черновика dev-брифов — `scenarios/dev-01…03/brief.md` (стоматология, пекарня с доставкой, библиотека вуза; малый, средний и крупный): на них настраиваются промпты агентов. Скрытые требования и персоны к ним — в тех же папках (T-303); 12 test-сценариев не открываются до S6.

```bash
uv run reqgraph-evals analyst --repeat 3                 # free-профиль, все dev-брифы
uv run reqgraph-evals analyst --scenarios dev-02 --tag try
```

Прогоняет только intake → Analyst и затем те же проверки, что `reqgraph check`. Отчёт `reports/analyst-YYYY-MM-DD-<профиль>[-tag].csv` — строка на сценарий и повтор (модель, провайдер, температура, seed, хэш промпта, версия пакета, вызовы, токены, $, время, применён ли патч, был ли повтор, сколько отброшено, число требований и ролей, требования с нарушениями ISO-001/003 и их доля, счётчики ISO-001…005, TRC-001, TRC-006, ошибка прогона) и `.md` со сводкой. Порог T-202 — не больше 15% требований с нарушениями ISO-001/003.

## Modeler на dev-брифах (T-203)

```bash
uv run reqgraph-evals modeler --repeat 3
```

Прогоняет intake → Analyst → Modeler и затем все проверки. Отчёт `reports/modeler-YYYY-MM-DD-<профиль>[-tag].csv|md`: модель и провайдер Modeler, хэш его промпта, сколько ответов понадобилось (≤ 3), число ФТ, процессов, задач и сущностей, SCH-001…003, процессы с SND-001 и доля процессов без них, SND-002…004, TRC-002…004, токены, $ и время всех вызовов. Порог T-203 — SCH-002 чист во всех прогонах, без SND-001 — не меньше 80% процессов.

## Standards на dev-брифах (T-204)

```bash
uv run reqgraph-evals standards --repeat 3
```

intake → Analyst → Modeler → Standards и все проверки. Отчёт `reports/standards-YYYY-MM-DD-<профиль>[-tag].csv|md`: модель Standards, хэш промпта, был ли повтор, число разделов, пустых обязательных (TPL-001) и доля заполненных, терминов в глоссарии, длина назначения и области, токены, $ и время всех вызовов. Порог T-204 — не меньше 80% обязательных разделов.

## Цикл ремонта на dev-брифах (T-205)

```bash
uv run reqgraph-evals repair --repeat 3                     # Reviewer на LLM
uv run reqgraph-evals repair --repeat 3 --reviewer template # абляция «без Reviewer»
```

Весь граф прогона в режиме brief: агенты, проверки, Reviewer и ремонт до сходимости, `needs_human` или лимита кругов. Отчёт `reports/repair-YYYY-MM-DD-<профиль>-<reviewer>[-tag].csv|md`: модели всех ролей, кругов ремонта, причина остановки, ошибок в первом и последнем отчёте, какие проверки остались с ошибками, ошибки SCH-* и процессы без ошибок SND-* (DoD S2), предупреждений, вызовов LLM, токены, $ и время. Критерий T-205 — каждый прогон сходится или останавливается с needs_human.
