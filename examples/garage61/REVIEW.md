# Проверка эталона garage61

Статус: **черновик, нужна проверка автора проекта.** Файлы написаны Claude по плану из `docs/tech-design`. Пока ты их не проверил, это не эталон, а предложение.

## Зачем нужен эталон

1. **Тестовая опора для ядра (S1).** На нём проверяются чтение и запись проекта (T-102), компилятор BPMN (T-103) и все 21 проверка (T-105–T-107). Эталон должен проходить их без ошибок.
2. **Мутационные тесты.** Код автоматически портит эталон и ждёт конкретную ошибку. Если эталон неверен, тесты будут проверять неправильное поведение.
3. **Образец для агентов.** Фрагменты эталона пойдут в промпты как примеры хорошего результата.
4. **Демо.** На нём показывается, как выглядит «зелёный» проект.

Эталон должен быть независим от кода проверок. Поэтому его пишет и утверждает человек, а не Claude Code в той же сессии, где пишутся проверки.

## Что уже проверено автоматически

- [x] все ссылки (`refines`, `realized_by`, `derived_from`, `actor`) указывают на существующие узлы и реплики
- [x] каждое BR уточнено хотя бы одним UR, каждое FR реализовано хотя бы одним элементом модели
- [x] у каждого элемента модели (задачи процессов, сущности, use case, контейнеры C4) есть требование, сирот нет
- [x] `realizes` в процессах совпадает с `realized_by` в требованиях
- [x] у всех FR есть критерии приёмки, у всех NFR — характеристика ISO 25010, метрика, единица, порог и метод
- [x] нет слов из словаря размытых формулировок («быстро», «удобно», «и т. д.», TBD …)
- [x] процессы: один старт, все узлы достижимы и ведут к концу, у веток xor есть подписи
- [x] покрытие интервью по 9 областям не ниже порогов (`interview/coverage.json`)
- [x] DBML разбирается `pydbml`, PlantUML компилируется (PlantUML 1.2022)
- [ ] Structurizr DSL не компилировался: Kroki недоступен из среды, где готовился эталон
- [ ] BPMN XSD и soundness через PM4Py: появятся после T-103 и T-106

## Что проверить тебе

- [ ] Предметная область правдоподобна: так ли работает небольшой автосервис? Чего явно не хватает?
- [ ] Каждое требование — одно утверждение, его можно проверить, критерии приёмки однозначны.
- [ ] Цифры условные (15% → 7% неявок, 60% онлайн, 600 000 ₽). Устраивают как пример?
- [ ] CON-001: ссылка на 152-ФЗ, ст. 18, ч. 5 (локализация персональных данных) — сверь формулировку.
- [ ] PRC-01: порядок шагов (сначала телефон, потом услуга) и петля «слот занят → показать слоты снова».
- [ ] PRC-02: событийный шлюз «ответ клиента / наступило время за 2 ч» правильно отражает правило отмены.
- [ ] ERD: поля и связи; нет ли лишних или недостающих сущностей (оплата частных клиентов намеренно вне рамок).
- [ ] Use case и C4: названия и границы системы.
- [ ] Транскрипт интервью звучит как живой разговор и не подсказывает требования, которых клиент не говорил.
- [ ] После проверки поменяй `status: reviewed` на `status: approved` в `requirements/*.yaml`: агенты не меняют утверждённые узлы.

## Соглашения, которые эталон фиксирует (подтверди или поправь)

| № | Соглашение | Где используется |
|---|---|---|
| 1 | Рёбра хранятся в узле-источнике: `refines`, `realized_by`, `derived_from` в `requirements/*.yaml`. `realizes` в DSL процесса — зеркало `realized_by` и обязано с ним совпадать. `trace/edges.yaml` генерируется, руками не правится. | T-101, T-102, TRC-004 |
| 2 | Область покрытия интервью — поле `area` в узле. Для `data` считаются сущности ERD. | coverage.py, T-301 |
| 3 | Id элементов моделей: DBML — `Note: 'ENT-xx · Название'` внутри таблицы (название по-русски — для TRC-005); PlantUML — псевдоним без дефиса (`UC01` = `UC-01`, `ACT01` = `ACT-01`); Structurizr — свойство `reqgraph.id`. | T-104 |
| 4 | Проверка сирот TRC-003 касается задач процессов, ENT, UC, C4-CNT, C4-EXT. Не касается событий, шлюзов, акторов, C4-SYS, атрибутов и диаграмм последовательности. | T-107 |
| 5 | ISO-002 срабатывает на два действия в одном требовании, а не на перечисление объектов («с длительностью и ценой»). | T-107 |
| 6 | `derived_from` ссылается на реплики заказчика (`role: client`). | TRC-006 |
| 7 | Фрагменты-иллюстрации в `docs/tech-design` (например, FR-007 в PRC-01) упрощены. Источник правды — этот эталон. | вся документация |
